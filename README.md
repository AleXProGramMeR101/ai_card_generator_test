# Генератор карточек товаров для B2B-магазина КИП

По JSON с данными о приборе сервис готовит черновик карточки товара: SEO-заголовок (до 70 символов), SEO-описание (800-1200 символов), таблицу характеристик, 3-5 поисковых запросов, подсказки для менеджера и список того, что нужно уточнить.

Главное правило: **характеристики не выдумываются**. Таблицу собирает код из входных данных, а все числа в текстах сверяются с входом. Если данных нет, в карточке так и написано: «данных нет».

## Запуск (Windows)

Нужен Python 3.10+ ([python.org](https://www.python.org/downloads/), при установке отметьте «Add python.exe to PATH»).

**1. Установка**

```bat
git clone <ссылка на репозиторий> card-generator
cd card-generator
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
copy .env.example .env
```

**2. Ключ Groq**

1. Зайдите на [console.groq.com](https://console.groq.com) и войдите (через Google, GitHub или почту). Из России сайт и API работают только через VPN.
2. Откройте раздел **API Keys** и нажмите **Create API Key**. Скопируйте ключ: он показывается один раз.
3. Откройте `.env` (`notepad .env`) и заполните две строки:

```
LLM_BASE_URL=https://api.groq.com/openai/v1
LLM_API_KEY=ваш_ключ
```

**3. Запуск**

```bat
.venv\Scripts\python server.py
```

Откройте **http://127.0.0.1:8000**, перетащите JSON-файл в окно загрузки или нажмите на один из примеров.

Без браузера, в консоли: `.venv\Scripts\python main.py examples\input` - карточки появятся в папке `output`.

## Формат входного файла

Один товар или список товаров. Обязательно только `name`:

```json
{
  "name": "Манометр показывающий DM 02",
  "manufacturer": "Манотомь",
  "specs": {"диапазон измерений": "0–1,6 МПа", "класс точности": "1,5"},
  "description": "Прибор предназначен для измерения избыточного давления..."
}
```

Битый JSON, пустые поля и товары без данных не роняют сервис: каждая ошибка показывается понятным сообщением.

## Примеры

В `examples/input` три товара, в `examples/output` - результаты прогона.

## Как это работает

1. Код определяет категорию товара и по её схеме (`schemas/manometer.yaml`) смотрит, каких важных характеристик не хватает.
2. Один запрос к модели (`openai/gpt-oss-120b`) возвращает тексты карточки в строгом JSON.
3. Код проверяет ответ: нет ли чисел, которых нет во входе, оценок вроде «надёжный» или «высокая точность», фраз вроде «в описании не указано», правильная ли длина. При ошибках модель получает их список и исправляет ответ. Слишком длинное описание код сам обрезает по границе предложения.
4. Всё сомнительное попадает в блок «Требует уточнения»: недостающие характеристики, оборванный текст, противоречия, важные значения, которые модель нашла только в описании.

Если для категории нет схемы, модель предлагает список характеристик, а карточка получает статус «требует проверки».

## Промпты и решения

Промпты - в `card_generator/prompts.py`.

- **Проверки делает код, а не промпт.** Запрет выдумывать есть и в промпте, но надёжность обеспечивают проверки после ответа.
- **Один запрос вместо цепочки** - быстрее, дешевле и укладывается в бесплатные лимиты Groq.
- **Мало данных - без генерации.** Если, кроме названия, ничего нет, модель не вызывается.
- **Модель меняется в `.env`.** Подходит любой OpenAI-совместимый API: Groq, OpenAI, локальные Ollama и vLLM.

## Ограничения

- Нечисловые выдумки («подходит для пищевой промышленности») ловятся только частично.
- Если модель неверно поняла факт из описания, он помечается в таблице, но может остаться в тексте.
- Схема характеристик пока одна - для манометров.
- Поисковые запросы - гипотезы: частотность по Вордстату не проверяется.
- Бесплатный Groq ограничен 8 тыс. токенов в минуту: на большом файле придётся ждать.
